# knedio-site

One-page personal portfolio for Karl Naio Edio. Next.js 16 (App Router, Turbopack, Cache Components), React 19,
Tailwind CSS v4, TypeScript strict. Deployed on Vercel. Everything is statically prerendered.

## Commands

- `npm run dev`: local dev server on http://localhost:3000
- `npm run check`: lint, typecheck and format check. Run it before every commit.
- `npm run format`: apply Prettier (with Tailwind class sorting)
- `npm run build`: production build; must stay fully static (every route `○`)

## Layout

```
src/
  app/                 routes and metadata files (layout, page, not-found, icon, OG image, robots, sitemap)
  components/          shared building blocks (Section, Reveal, ExternalLink, header, footer)
  components/sections/ one file per page section, rendered in order by app/page.tsx
  content/site.ts      every word, link, date and image the site shows
  content/media/       images, imported statically so Next generates sizes and blur placeholders
```

## Standards

**Content**

- All copy lives in `src/content/site.ts`. Components never hardcode user-visible text; add a field (headings go in
  `copy`) and read it. Keep the shapes typed and drop fields nothing reads.
- Images are static imports from `content/media/` with meaningful `alt` text, rendered with `next/image`,
  `placeholder="blur"` and an accurate `sizes`.
- Write copy plainly and in the first person. Use curly quotes and apostrophes (’ “ ”) in copy.

**Components**

- Arrow-function components, named exports (`export const Hero = () => ...`). Default exports only where Next requires
  them (`page`, `layout`, `not-found`, metadata routes). ESLint enforces `func-style`.
- File names are kebab-case and match the export (`section.tsx` exports `Section`).
- Server components by default. Add `"use client"` only for real browser state (`site-header`, `local-time`); keep
  client components small and leaf-level.
- A new section: create it in `components/sections/`, wrap it in `<Section id index label>`, give its `h2` the id
  `${id}-heading`, add it to `app/page.tsx` and to `navigation` in `site.ts` so the menu and the page stay in sync.
- Outbound links use `<ExternalLink>`, which sets `target`/`rel` and the screen-reader hint.
- Imports: external packages, a blank line, then `@/` aliases. No relative `../` imports across folders.

**Styling**

- Tailwind v4 with design tokens in `src/app/globals.css` `@theme`. Use the tokens (`text-fg`, `text-muted`,
  `bg-surface`, `border-line`, `text-title`, `ease-out-quint` ...) rather than raw hex values or one-off sizes. Add a
  token when a value repeats.
- Shared patterns are the component classes in `globals.css`: `shell`, `grid-12`, `label`, `link-draw`, `link-rule`,
  `reveal`. Reuse them before writing new utility strings.
- Motion is CSS-only (`<Reveal>` uses scroll-driven animation) and must respect `prefers-reduced-motion`. No animation
  libraries.
- Dark theme only (`colorScheme: "dark"`).

**Accessibility and SEO**

- One `h1` per page; each section is labelled by its heading (`aria-labelledby`). Keep the skip link working (`#main`).
- Decorative icons get `aria-hidden="true"`. Interactive elements need a visible focus state.
- Metadata, OG image, sitemap and robots all read `site.url`. It resolves from `NEXT_PUBLIC_SITE_URL`, then Vercel's
  `VERCEL_PROJECT_PRODUCTION_URL`, then localhost. Never hardcode the domain.

## Next.js 16 notes

- APIs differ from older Next versions. Check `node_modules/next/dist/docs/` before using one you're unsure of.
- `cacheComponents` and `partialPrefetching` are on in `next.config.ts`; Tailwind runs through the Turbopack loader
  configured there.
- `LayoutProps<"/">` / `PageProps` are global route types generated by Next; no import needed.

## Before committing

`npm run check && npm run build` both pass, and the build output still shows every route as static.
